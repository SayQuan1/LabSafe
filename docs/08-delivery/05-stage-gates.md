# 08.5 设计、开发与发布的阶段门禁

适用：2026-09-27起的文档阶段；本文件用于纠正把“尚未实现”误判为“设计无法结束”的审计口径。

## 1. 三种完成状态

| 阶段 | 必须具备 | 不要求提前存在 |
|---|---|---|
| D 设计可编码 | 选型与获取路线、输入输出、业务守卫、数据约束、失败行为、配置和测试方法均明确；没有需要实现者自行裁决的关键分支 | 完整应用、训练后的项目权重、实测准确率、镜像digest、恢复演练成绩 |
| I 实现通过 | 代码/迁移/依赖锁文件/制品真实存在，单元/集成/故障测试和模型适配通过 | 用户上线批准 |
| R 允许试点/发布 | 真实模型和规则的来源/授权/评测、安全及恢复验证、业务风险接受记录齐全 | 不适用 |

协作者评审是另外的治理状态，不与D/I/R混用。文档可完成并提交评审，不需要等I/R全部通过；未经评审不能称为“已批准”。

## 2. 开工前的具体设计检查

1. 模型不能只写“以后选”：必须指定开发基线、版本来源、四类目标数据准备/训练路线、适配接口、失败后的处理以及替换条件。
2. 未取得权重/硬件测试结果时，相关任务记为I阶段待实施；不得编造hash、兼容性结论或性能。
3. 模型置信阈值为待校准配置；文档必须定义范围、比较运算、缺失处理、版本归属和变更权限。最终数值不是编码前必须实测完成的条件。
4. 工程验收可以现在冻结。安全业务验收必须有指标公式、数据/样本要求、明确的开发目标和正式审批流程；未批准不能被代码判为生产可用。
5. 数据库列/索引/FK/事务/迁移步骤在D阶段定义；空库执行DDL、Alembic迁移、启动Compose和恢复演练在I/R阶段执行。
6. 模拟模型只可用于dev/test；运行时必须隔离模拟/真实制品，生产不能因模型缺失自动回退模拟结果。

## 3. G项拆分规则

| 旧编号 | D阶段要解决 | I/R阶段保留的实施任务 |
|---|---|---|
| G-01 | 模型/数据/适配/校准路线与版本基线 | 模型下载许可核验、项目标注微调、真实adapter、依赖锁文件及硬件smoke |
| G-02 | 工程与业务验收分层、指标算法、目标与审批记录结构 | 真实样本、专家签署、冻结评测和试点风险接受 |
| G-03 | 数据库与部署验收任务、顺序、输入输出、失败处理 | 实际迁移、集成、故障注入、备份恢复与断公网测试 |

## 4. 设计变更控制

设计基线不是“未经验证也保证成功”。若首个技术验证推翻假设，提交有证据的ADR，修改模型/运行时或预算、同步契约和测试；不得让实现者静默替换架构。应用目标版本与实际可安装锁文件分别记录；不可下载或有不接受的许可时停止该制品发布，不影响不依赖它的业务开发。

## 5. Git交付边界

设计文档和契约可以独立形成docs PR；无需先创建业务代码。提交前检查当前分支/暂存差异、生成一致性、链接、无密钥或真实样本，再按CONTRIBUTING审核。远程推送是独立动作：本轮逐项解决设计问题不自动执行commit/push或修改原有暂存区。
