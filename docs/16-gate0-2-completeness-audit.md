## 编码前阻断项

1. 最终风险确认者必须是安全员、安全管理员或明确授权的安全负责人。
2. Finding 与 RemediationTask 状态联动必须固定，复查通过才允许闭环。
3. 风险评分的字段、因子和解释必须固定，评分不能替代人工安全结论。
4. 全局、租户、实验室规则的覆盖优先级和版本关系必须固定。
5. 断公网拓扑和本地资源清单必须能够通过验收。
6. API 错误、认证、上传限制、幂等和 OpenAPI Schema 必须有契约。
7. Outbox 至少一次投递、Worker 幂等和死信重放必须有明确语义。
8. 规则事实 Schema、来源和审批字段必须固定。
9. 原图、脱敏样本、数据集和模型之间必须可追踪。

## 8. 详细补漏清单

### 8.1 权限和状态

- 实验室负责人默认只能查看、补充说明和提出整改建议；只有明确授权为安全负责人时才可确认。
- Finding 只有复查通过后才能 closed；复查驳回回到 remediation_in_progress。
- 逾期是 RemediationTask 派生标志；无法整改必须由安全管理员确认。

### 8.2 风险与规则

- 首期采用可解释确定性 risk_score，不训练风险模型。
- 全局规则、租户规则、实验室例外按实验室例外 > 租户 > 全局生效。
- 规则必须有输入事实 Schema、来源、审批人、有效期和回归案例。

### 8.3 API、认证和上传

- Gate 3 前生成完整 openapi.yaml，包括状态码、Schema、错误码、幂等和弃用规则。
- 使用 HttpOnly、Secure、SameSite 会话 Cookie，Argon2id 密码哈希、登录限流和会话撤销。
- 上传仅允许 JPEG/PNG/WEBP，检查真实 MIME、可解码性、大小、像素上限并清理 EXIF/GPS。
- 原图访问使用短期预签名 URL，原图导出需要额外权限和审计。

### 8.4 任务和数据血缘

- Outbox 和业务事务同一 MySQL 事务提交，Publisher 至少一次投递，Worker 以幂等键和资源版本防重复。
- 训练血缘为原图 -> 脱敏派生图 -> 数据集版本 -> 模型版本。
- 删除原图时执行对象清理、派生样本引用检查和审计，不删除已经发布模型。

### 8.5 离线和运维

- 断公网时不得调用云 OCR、LLM、CDN、在线字体或外部 DNS。
- 模型、规则、前端资源和容器镜像必须预置在校内环境。
- CSV/PDF 导出异步执行，下载 URL 短期有效并绑定租户/实验室范围。
- Gate 3 为监控项补充阈值、持续时间、等级、责任人和关闭条件。
