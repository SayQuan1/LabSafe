# 08 安全、隐私与审计

状态：**待用户确认**

## 1. 数据治理

- 试点前取得学校/实验室书面授权，明确目的、范围、保存期限、访问者和撤回机制。
- 默认部署在校内服务器，原始图片不出校。
- 人员影像处理能力预留，但 PPE 识别暂不属于首期验收范围；如采集画面出现人员，训练前仍需打码/裁剪非必要人脸，禁止建立身份画像。
- 图片保留期限由校方政策配置；支持按项目/实验室删除，并保留不可逆审计摘要。

## 2. 访问控制

- 固定角色：安全管理员、实验室负责人、安全员/巡检员、整改责任人、只读查看者。
- 资源权限按实验室范围和动作粒度控制。
- 本地账号起步，密码哈希、登录限流、会话过期和强制登出。
- 预留学校统一认证接口，但不作为首期阻塞条件。

## 3. 审计要求

审计事件至少包括：登录、数据访问、图片上传/删除、AI推理、规则发布、人工修改、确认/驳回、任务派发、期限变更、复查、销项、导出和权限变更。

每条事件保存操作者、时间、资源、旧值、新值、原因、请求 ID 和客户端信息。审计记录不可由普通用户修改或删除。

## 4. 安全事件

若发生漏报、错误规则或数据泄露：

1. 标记事件并保留相关模型/规则版本。
2. 暂停受影响类别的自动建议，必要时回滚。
3. 由安全专家和项目负责人复盘，形成纠正措施。
4. 更新规则/模型后重新跑冻结回归集。

系统任何时候都不得作为唯一安全依据。
