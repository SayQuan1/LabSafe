# 02 范围、验收标准与决策基线

状态：**待用户确认**

## 1. 六个月硬目标

完成可部署原型，并在至少两个实验室完成验证：一个实验室完成现场试用，另一个实验室完成历史数据回放；核心流程必须从采集走到复查销项。若真实合作方或安全专家不可得，必须降级为受控模拟场景，并明确标注未完成真实试点，不得伪造验证结论。

## 2. 验收分层

### P0：必须通过

- 用户可创建实验室、区域、货架/柜号、责任人和巡检模板。
- 用户可按模板采集图片，质量失败时得到可执行补拍提示。
- 能输出试剂名称和日期字段，支持人工修正。
- 能对至少 20 条专家确认规则执行相容性检查。
- 人工可逐问题确认、修改、驳回或标记无法判断。
- 可完成待派发、整改、复查、销项和逾期流程。
- 证据链包含图片、字段、规则和模型版本。
- 预置 Demo 在断网环境完成完整主流程。

### P1：应通过

- 支持试剂瓶、标签区域和相邻容器等 MVP 核心对象检测；PPE 和安全设施暂不属于验收范围。
- 单图完整推理目标不超过 30 秒，失败和重试状态可观察。
- 导出 CSV/PDF 报告。
- 一个实验室完成现场试用，另一个实验室完成历史数据回放。
- 输出算法测试报告、业务对照报告和用户反馈。

### P2：可延后

视频流、传感器、边缘端完整离线推理、自动库存盘点、统一认证、外部消息系统深度集成。

## 3. 评测口径

- 高风险召回率：按独立风险问题统计，并按问题类别分别报告。
- 高风险门槛：受 20 天周期限制，第 1-3 天冻结最小基线集，第 4-7 天确定临时迭代门槛，第 8-10 天冻结候选验收集；项目报告必须区分临时门槛、正式门槛、样本量和未覆盖场景。
- 真实现场数据为主要验证/测试依据，合成增强数据只用于训练增强。
- 业务对照：人工巡检 vs. LabSafe 辅助巡检，比较耗时、问题发现数、误报、漏报、任务按期率和用户操作步骤。

## 4. 失败与降级规则

- 数据不足：保留标签名称/日期与相邻存放两条主线，削减非主线类别。
- 算力不足：降低分辨率、异步处理或切换 CPU，不阻塞业务记录。
- OCR 失败：人工录入，确认前不执行相容性判断。
- 新模型/规则变差：保留旧版本并回滚，历史记录不改写。
- 高风险指标未达标：如实报告错误类型与适用边界，不修改测试集、不挑选性展示。
- 时间不足：优先削减非核心类别、复杂报表和外部集成，保留复核、整改、复查、证据和版本留痕。

## 5. 不可妥协的安全边界

- 系统不得作为唯一安全依据。
- 模型置信度不能替代安全严重度。
- 无法判断不得自动转为安全或违规。
- 规则层不得由大模型直接生成最终结论。
- 任意临时覆盖都必须有操作者、原因、期限和批准记录。
