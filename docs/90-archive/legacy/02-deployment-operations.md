# 10 部署、运维与监控

状态：**待用户确认**

## 1. 首期部署形态

单台校内服务器运行 Vue Web/API、Celery Worker、AI 推理、MySQL、MinIO 和 Redis。服务器规格尚未提供；设计必须先定义最低 CPU/内存/磁盘配置。GPU 可选；GPU 不可用时切换 CPU 或降低分辨率，核心流程仍可运行。

## 2. 环境

- `dev`：开发与单元/集成测试。
- `staging`：接近试点配置，使用脱敏或模拟数据。
- `pilot`：校内真实试点，生产权限和数据隔离。
- Demo 账号和数据不可进入真实试点数据库。

## 3. 发布与回滚

- 应用、模型和规则分别版本化。
- 发布前执行数据库备份、迁移演练、回归集和健康检查。
- 新版本保留上一稳定版本，按实验室/任务记录具体版本。
- 模型/规则指标变差时可单独回滚，不重写历史记录。

## 4. 监控告警

必须监控：接口成功率、队列长度、单图推理耗时、任务超时、失败重试、GPU/CPU/内存/磁盘、低置信度比例、人工驳回率、类别误报率、长期处理中任务、对象存储容量和备份结果。

告警级别：

- P1：数据不可访问、任务大量失败、权限异常、备份失败。
- P2：推理超时上升、队列持续积压、某类别误报/驳回异常。
- P3：单用户上传失败、报告生成延迟、容量接近阈值。

## 5. 备份与恢复

- MySQL 定期全量/增量备份，MinIO 图片和报告单独备份。
- 至少每月执行一次恢复演练，记录 RPO/RTO 实测值。
- 备份内容受同等访问控制和保留策略约束。
