# 07 前端信息架构与交互规范

状态：**待用户确认**

## 1. 页面结构

### 移动巡检端

1. 登录
2. 选择实验室/巡检模板
3. 检查项列表与进度
4. 拍摄/上传与质量提示
5. AI结果和证据复核
6. 我的整改任务
7. 复查拍摄与提交

### Web管理端

1. 总览看板
2. 实验室、区域、人员和权限
3. 巡检记录
4. 风险问题
5. 整改任务
6. 规则与模型版本
7. 报表导出
8. 审计日志

## 2. 关键交互

- 检查项显示 `未开始 / 处理中 / 待复核 / 已完成 / 需补拍`。
- 结果页将图片证据、检测框、OCR字段、规则依据和风险等级放在同一上下文中。
- “确认问题”“无法判断”“驳回”“补拍”必须是明确动作，不能仅靠颜色区分。
- 无法判断必须要求选择原因，例如模糊、遮挡、标签不可读、规则缺失。
- 复核修改显示旧值、新值和修改原因。
- 任务页突出责任人、期限、逾期状态、最新证据和复查动作。

## 3. 视觉与可用性

- 以工作台和扫描效率为主，避免营销型首屏和装饰性卡片堆叠。
- 颜色只表达状态，不作为唯一信息；高风险同时显示文本和图标。
- 拍摄按钮、补拍、确认、复查等主要动作在手机单手可达区域。
- 结果处理中显示阶段和预计状态；超过 30 秒进入可离开页面的异步状态。
- 所有表格支持筛选、排序、分页和导出。

## 4. 错误和空状态

- 图片上传失败：保留本地草稿并可重试。
- 推理失败：显示稳定错误码和“稍后重试”，不显示虚假的安全结论。
- 无规则匹配：显示“规则缺失/待确认”。
- 没有发现问题：显示“在本次图片和规则范围内未发现”，而不是“绝对安全”。
