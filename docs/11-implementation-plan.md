# 11 六个月实施计划与责任分工

状态：**待用户确认**

## 1. 责任域

| 责任域 | 交付责任 |
|---|---|
| 产品/试点 | 需求、模板、用户培训、专家协调、对照实验和反馈 |
| 算法/数据 | 采集规范、标注、模型基线、规则输入、评测和困难样本 |
| 后端/平台 | API、数据库、队列、对象存储、权限、审计和部署 |
| 前端/体验 | 响应式采集、复核、整改、看板、报表和可用性 |

每个责任域指定一名负责人；共同责任不替代明确负责人。

## 2. 月度计划

### 第1月：基线与合作

- 确认合作实验室和安全专家。
- 完成数据授权、采集/标注规范和模板。
- 冻结 P0/P1 验收口径与第一版测试集方案。
- 验证质量检测、检测、OCR和规则基线。

### 第2月：数据和骨架

- 完成首轮现场采集、标注和困难样本池。
- 建立 MySQL/MinIO/Redis、API、队列和模型登记骨架。
- 完成目标检测/OCR初版和化学品实体表。

### 第3月：核心算法

- 优化反光、倾斜、小目标和遮挡场景。
- 完成实体标准化、至少 20 条规则和严重度映射。
- 冻结第一版测试集，确定高风险召回率门槛。

### 第4月：业务系统

- 完成实验室、巡检、复核、待派发、整改、复查和销项。
- 接入异步推理、对象存储、权限、审计和报表。
- 完成断网 Demo 路径。

### 第5月：联调与试点

- 完成端到端、性能、异常、权限和恢复测试。
- 在第一个实验室试运行，收集人工复核和用户反馈。
- 模型/规则更新走版本发布流程。

### 第6月：验证与交付

- 在一个实验室完成现场试用，在另一个实验室完成历史数据回放。
- 完成人工 vs. 辅助巡检对照实验。
- 完成算法报告、业务报告、试点反馈、Demo脚本和部署文档。

## 3. 里程碑退出条件

- M1：合作、授权和验收口径确认。
- M2：数据集、API骨架和可运行基线完成。
- M3：规则、测试集和评测脚本冻结。
- M4：核心业务闭环可端到端运行。
- M5：第一个实验室试运行且无 P1 阻断缺陷。
- M6：两个实验室数据和交付材料齐备。

## 4. 变更控制

每月评审新增需求的价值、风险、工期和是否挤出既有验收项。涉及安全边界、数据范围、指标或 MVP 的变更必须重新获得用户确认。
