## 确认规则

- 用户确认前：只允许修改文档，不创建业务代码、数据库迁移或部署资源。
- 用户确认后：按第 11 份文档的顺序实施，并在每个里程碑回写实际状态。
- 任何涉及安全责任边界、数据处理范围、验收指标或 MVP 范围的变化，都需要重新确认。

## 当前已确认的核心基线

- 首期用户为高校实验室安全管理部门，先深耕一个实验室，再扩展到至少两个实验室。
- MVP 主线为试剂名称/日期核验，以及同柜相邻存放的不相容化学品判断。
- AI 只提供辅助证据；风险结论必须由授权安全人员确认。
- “无法判断”是独立状态，不得伪装成安全或违规。
- 采用校内单服务器、响应式 Web；完整结果目标为 30 秒内，完全断网只保证预置 Demo。
- 以冻结测试集上的高风险问题召回率为首要算法指标，并如实报告未达标情况。
- 业务闭环必须覆盖采集、识别、复核、派发、整改、复查、销项、报表和证据留痕。
- 首期不做视频流、传感器、完整边缘离线推理和自动库存盘点。
